  1. discover — 按 target 用 EndpointSlice(service)或 label(selector)列出 Ready 端点，按模型分桶（排空中端点自动排除）。
  2. render — cart sink 拼 workers；openresty sink 改写或模板生成 peers（可 CART 优先 + 后端兜底，带 priority）。
  3. diff & write — 和上次比，变了才写 ConfigMap；发现为空 保留上次（fail-safe），绝不写空。
  4. propagate — ConfigMap 整卷挂进消费方 pod（kubelet ~1min，非 subPath）。
  5. reload — sidecar inotify 到变化 → SIGHUP 主进程优雅重载；坏配置只 warn、保留旧配置。

关键设计

发现：EndpointSlice 优先，label 兜底

service 走 EndpointSlice——原生 Ready / Terminating 语义，排空中端点自动排除，前提是 Service 只选服务端点（LWS Service 配成只选 leader）；没建 Service 的单机 / 单卡用 selector。

CART 优先 + 后端兜底

一条 route 的 peers 可多来源带 priority：CART 作 priority-1 优先、后端桶作 priority-0 兜底——CART 挂了 openresty 直连后端，不丢流量。

免重启热更

agent 每周期重读 config，变了重建 sinks；加 / 删模型只改配置（config 也走 ConfigMap 挂载）。读失败保留上次好配置。

一个二进制，两个角色

agent 做发现；同一个二进制 --reload-mode 当 sidecar，靠 shareProcessNamespace 给同 pod 主进程发 SIGHUP。CART / openresty 零改。

数据平面里 openresty 的 peers 也可以直连后端（不经 CART）——是否插 CART、CART 优先还是纯 CART，全由 agent 配置的 sources 决定，代码不变。
